**AICO-Intellig v4 修正重跑与补强实验汇总：2026-09-16**

本轮工作的目标，不是继续扩大同类扫描，而是把 `v4` 协议核验后暴露出的两个真实缺口补干净：

1. 随机方向基线的步长网格偏保守，导致旧版 `v4` / `xlarge` 的优势幅度被高估；
2. 首达调用数的记账存在提前一次的问题，会污染首达与摊销统计。

在修脚本之后，又补跑了四类直接服务于理论解释的实验：

- repaired `strict v4`
- repaired `strict v4 large / xlarge`
- `history noise @ d=256`
- `platform ablation`
- `mismatch + noise @ d=256`

## 一、代码层修正

### 1. 随机方向步长网格扩展

旧版候选：

- `0.05, 0.1, 0.2, 0.4`

修正版候选：

- `0.05, 0.1, 0.2, 0.4, 0.8, 1.6`

验证集最优步长普遍落在新扩出的上边界附近，因此旧版随机方向基线确实偏弱。

### 2. 首达调用数记账修正

`fd_descent` 和 `rand_dir_descent` 的 `best_trace` 已改为按真实查询顺序逐次更新，不再把第二次差分查询发现的改进提前记到前一位。

这个修正通常不改变最终 simple regret，但会影响：

- first-hit query
- threshold-hitting trace
- amortized payback 统计

因此属于必须修复的问题，而不是展示层小瑕疵。

## 三、理论解释补强实验

### 1. history noise @ `d=256`

在 `8` 个历史任务、每任务 `2` 个 probe 的配置下：

- `noise=0.0`: projector error `0.0074`, regret `0.0079`, success@`0.02` `0.9688`
- `noise=0.1`: projector error `0.1709`, regret `0.0198`, success@`0.02` `0.9792`

说明：

- 噪声会显著放大子空间估计误差；
- 但在当前 synthetic family 中，下游 transfer 并没有立刻崩掉；
- 更合适的表述是“噪声下渐进退化”，而不是“轻微噪声即失效”。

### 2. platform ablation

代表性结果：

`d=64, budget=180, radius=0.5, fd_eps=1e-3`

- `estimated_anchor`: `0.0023`
- `estimated_free`: `0.0001`
- `oracle_anchor`: `0.0023`
- `oracle_free`: `0.0004`

说明：

- 旧版反复出现的 `~0.006` 平台，不能直接解读为“结构学习已经接近最优”；
- anchor / radius / optimizer setting 本身会制造相当一部分平台误差；
- 因此理论上应把平台项作为优化器约束项单独建模，而不能简单并入结构估计误差。

### 3. mismatch + noise @ `d=256`

代表性结果：

`angle=45, ambient=0.01, noise=0.1`

- projector error `0.7257`
- estimated-subspace regret `0.0127`
- success@`0.02` `0.8778`

说明：

- 联合扰动下收益仍然存在；
- 但角度退化目前还不够单调，暂时不适合直接写成 sharp boundary。

## 四、现在可以更硬地说什么

当前最稳妥的表述应当是：

1. 在修正公平性与基线调参后，共享结构降低跨任务查询复杂度的现象仍然稳定存在。
2. 该收益已经在更大样本、更高共享维度、更高预算和一定噪声条件下得到复现。
3. 收益对噪声与失配表现为渐进退化，而不是轻微偏离即失效。
4. 旧版 `~0.006` 平台不能再被直接解释为“结构学习已接近理论极限”，平台中包含明显的优化器侧成分。

## 五、现在还不能过度声称什么

1. 这些结果仍然主要来自受控 synthetic family，不是普适黑箱优化定理。
2. `mismatch + noise` 的角度响应还不够干净，不能直接抽象成严格退化律。
3. 高维真实任务证据仍缺，`CorcaSim` 还没有完整接进 `history -> transfer -> amortization` 链条。
